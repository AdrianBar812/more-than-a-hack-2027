Ideas of models

approach: Heuristics + HMM/Viterbi

spellF1 expectation: likely above the baseline
main risk: transition penalty needs choosing without tuning on the public window
────────────────────────────────────────
approach: LightGBM on window features + smoothing
needs labels from other games?: yes
handles missing ball: good, since it can learn missingness
spellF1 expectation: potentially higher
main risk: the label source and format of other games
────────────────────────────────────────
approach: GRU / 1D-CNN / transformer + smoothing
needs labels from other games?: yes, more of it
handles missing ball: good
spellF1 expectation: potentially highest
main risk: needs the most data and tuning, and is harder to reproduce



=========================================
Important notes about files:
=========================================


..tactical_adt.txt
	each row has multiple tracks that represent the position of a player or the ball
		Each track has 3 values <position_x>:<position_y>:<speed>
		Tracks are not tied to one player (if the algorithm loses a player it can assign a different track to the same player once is tracked again)
		All the track values are already normalised to filed position 
		Homography is already applied

..tactical_adt.xml
	Has more information about the tracks
		There are 44 tracks possible
		Each track can represent diffrent players BUT ALWAYS the same team
		?Attributes when the game starts/half time/ end (questionmark bcs im not sure)
		?I think goalkeepers have a different attribuite

..tactical_homography.csv
	Each row represent a 3x3 matrix with homography information
	Kinda useless because the transformation are already applied
	Might be usefull as reference if we plan to use any additional datasets

..tactical_smart_tagging.xml
	Has attribuites that give more context to what is happening in the game
		Free kicks/ penalties/ etc
		Might be usefull for special cases.
